# Aether Clash 仓库吸引力与完善计划

目标：把 `Aether Clash` 从“能运行的 MOBA 原型”打磨成“陌生人愿意点开、愿意试玩、愿意 star、愿意继续关注”的原创开源游戏项目。

重要前提：

- 不承诺一定能火。Star 来自可玩质量、展示质量、传播渠道、发布时间和持续迭代。
- 不复制《王者荣耀》、漫威或其他第三方 IP 的角色、美术、音效、文案和具体数值。
- 先把 1v1 做成有记忆点的垂直切片，再扩展 3v3 / 5v5。

## 为什么现在没人 star

当前仓库的问题不是没有工作量，而是对陌生人缺少即时吸引力。

| 问题 | 当前表现 | 影响 |
| --- | --- | --- |
| 第一眼没有画面 | README 没有截图、GIF、视频或 release 图 | 用户不知道游戏长什么样，容易直接离开 |
| 卖点不够锋利 | 描述偏“学习原型”和“标准库实现” | 对玩家不够像游戏，对开发者不够像可研究项目 |
| 试玩成本仍高 | 需要 clone 后运行 `python main.py` | 非 Python 用户不一定愿意试 |
| 玩法记忆点不足 | 有 MOBA 系统，但缺少独特机制 | 用户难以说出“这个游戏特别在哪里” |
| 展示缺少路线感 | 有 roadmap，但没有版本目标和完成度徽章 | 用户不知道项目是否会持续变好 |
| 缺少传播材料 | 没有短视频、GIF、截图、release notes | 发到社区时没有可传播素材 |

## 项目重新定位

建议仓库定位从：

> Python 标准库 MOBA 原型

调整为：

> A tiny open-source 2D MOBA you can run, mod, and learn from.
>
> 一款可运行、可改造、可学习的开源 2D MOBA 小游戏。

面向三类用户：

| 用户 | 他们关心什么 | README 要给什么 |
| --- | --- | --- |
| 玩家 | 好不好玩、有没有画面、能不能快速打开 | GIF、截图、下载包、操作说明 |
| 初学者 | 能不能读懂、能不能改英雄 | 模块结构、改英雄教程、简单任务 |
| 开源关注者 | 是否持续迭代、是否有潜力 | roadmap、issues、版本计划、贡献入口 |

## 版本目标

### v0.2：1v1 可玩垂直切片

目标：让用户 clone 后 3 分钟内能打一局，并理解胜利目标。

必须完成：

- 新手引导层：第一次进入显示移动、普攻、技能、购买、推塔、水晶目标。
- 英雄详情：选择页显示技能说明、难度、推荐出装、定位。
- 局内反馈：击杀、推塔、升级、购买、野怪刷新、远古守卫刷新都有明显提示。
- AI 强化：敌方英雄会购买装备、按职业打法行动，并更主动争夺资源。
- 结算增强：显示伤害、承伤、经济、推塔、野怪、KDA。
- README 加首屏 GIF、3 张截图和 30 秒试玩说明。

验收标准：

- 新用户不看源码也能知道怎么玩。
- 一局能自然结束，不需要靠猜。
- README 首屏能看到真实游戏画面。

### v0.3：游戏感增强

目标：让它看起来更像游戏，而不是 Tkinter 技术 demo。

必须完成：

- 增加原创音效：按钮、购买、升级、技能、击杀、推塔、胜负。
- 技能特效按英雄区分，不再只是通用圆圈/线条。
- 小地图增强：资源刷新、敌方消失、塔状态、兵线压力。
- 装备系统扩展到 18-24 件，并加入更明确的被动。
- 英雄扩展到 8-10 个，每个英雄有清晰连招和弱点。
- 加设置页：语言、音效开关、特效密度、按键说明。

验收标准：

- 截图/GIF 能看出不同英雄的差异。
- 玩家能从装备和技能选择里做出不同打法。
- 对局反馈不遮挡视野，但关键信息足够明显。

### v0.4：可分享版本

目标：让不会 Python 的用户也能试玩。

必须完成：

- 提供 Windows 可执行包或 zip release。
- GitHub Releases 写清版本亮点、截图和运行方法。
- README 增加 `Download`、`Gameplay GIF`、`What makes it interesting`。
- 增加 `CONTRIBUTING.md`、`CHANGELOG.md`、issue templates。
- 增加 `good first issue` 任务：新英雄、新装备、音效、UI polish。

验收标准：

- 用户不装依赖也能下载试玩。
- 仓库看起来像持续维护的开源游戏，而不是一次性作业。

### v0.5：pygame 迁移起点

目标：保留当前玩法系统，把表现层迁移到更适合游戏的运行时。

必须完成：

- 保留数据、战斗、AI、经济逻辑，抽象渲染和输入接口。
- 新建 pygame runtime，先复刻当前 1v1。
- 支持 sprite、动画帧、音频混音、固定帧率和资源目录。
- 迁移后再考虑 3v3 / 5v5。

验收标准：

- `python main.py` 仍能运行当前版本。
- `python pygame_main.py` 能运行 pygame 版本。
- 玩法逻辑不重复写两套。

## README 改造计划

README 首屏需要从“说明项目”变成“展示游戏”。

建议结构：

1. 标题 + 一句中英卖点。
2. GIF 或截图，必须是真实游戏画面。
3. 三个最强卖点：
   - playable 1v1 MOBA
   - moddable heroes/items
   - no install dependencies 或 release download
4. 快速开始。
5. 当前版本亮点。
6. 截图。
7. 英雄/装备/模式。
8. 开发路线。
9. 贡献方式。

必须补的素材：

- `assets/screenshots/lobby.png`
- `assets/screenshots/hero-select.png`
- `assets/screenshots/match.png`
- `assets/screenshots/shop.png`
- `assets/screenshots/settlement.png`
- `assets/demo/aether-clash-gameplay.gif`

## 游戏独特卖点设计

不能只做“低配王者”，需要自己的记忆点。

建议保留并强化这些原创方向：

| 卖点 | 玩法表现 |
| --- | --- |
| 小而完整 | 单人 1v1，几分钟一局，系统完整 |
| 可改英雄 | 英雄数据集中，技能逻辑清晰，适合学习和二创 |
| 双语开源 | 中文和英文玩家都能读、能玩 |
| 轻量运行 | 标准库版无需安装依赖，pygame 版后续做更强表现 |
| 可扩展 MOBA 沙盒 | 支持新增英雄、装备、AI、地图目标 |

可新增的原创机制：

- 星辉能量：击败野怪、推塔、连杀都会积累能量，能量可短时间强化技能。
- 兵线号令：击败中心目标后可选择强化上/中/下某一路兵线。
- 英雄专属被动：每个英雄都有一个简单但改变打法的被动。
- 装备流派：攻击、法术、防御、机动、打野都有清晰推荐路线。

## 两周执行清单

### 第 1-2 天：展示基础

- 截 5 张真实游戏截图。
- 录 30 秒 GIF。
- README 首屏放 GIF 和下载/运行入口。
- 加 `assets/screenshots/` 和 `assets/demo/`。

### 第 3-5 天：1v1 新手体验

- 增加新手引导 overlay。
- 增加技能详情和升级收益。
- 增加装备详情面板。
- 修掉遮挡视野和提示过大的 UI。

### 第 6-8 天：战斗爽感

- 加塔攻击预警线。
- 加击杀、推塔、连杀、远古守卫刷新播报。
- 加英雄专属技能特效。
- 加基础音效。

### 第 9-11 天：AI 和成长

- 敌方 AI 自动购买装备。
- AI 按英雄职业调整打法。
- 结算页增加伤害、经济、推塔、野怪数据。

### 第 12-14 天：发布包装

- 做 Windows zip/release。
- 写 `CHANGELOG.md`。
- 写 `CONTRIBUTING.md`。
- 创建 v0.2 release。
- 发一条中文和英文项目介绍帖。

## Star 目标

| 阶段 | 目标 | 判断方式 |
| --- | --- | --- |
| 当前 | 0-5 stars | 主要来自自己测试和少量朋友 |
| v0.2 | 10-30 stars | README 有 GIF，1v1 可顺畅试玩 |
| v0.3 | 30-100 stars | 游戏差异明显，有截图/视频传播 |
| v0.4 | 100+ stars | 有 release 包、贡献入口和持续更新 |

Star 不是第一目标，第一目标是让项目足够清楚、足够好玩、足够容易试玩。做到这三点后，传播才有意义。
