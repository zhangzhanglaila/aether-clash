# 王者类 MOBA 对照开发计划

本文档用于把当前 `python_moba` 原型推进成更完整的原创王者类 MOBA。目标是学习同类产品的功能结构、交互层级和战斗节奏，不复制《王者荣耀》的英雄、皮肤、美术、图标、地图、音效、文案、品牌或具体数值。

## 当前原则

- 只实现同类 MOBA 的通用系统和体验，不照搬受保护内容。
- 先做可玩闭环，再补表现细节。
- 所有新增系统优先数据化，避免继续把配置写死在 `main.py`。
- 每一阶段都要有可验证结果，提交到 Git。
- 当前开发顺序由你确认如下：先完善 1v1，再扩展 3v3 / 5v5，之后迁移到 `pygame`。
- 双语保留，英雄数量尽量持续扩充。
- 音效如果有可用资源就直接接入，不为空缺项单独延后。

## 当前状态

已实现：

- 语言选择、大厅、模式选择、英雄选择、加载页、对局页。
- 5 个原创英雄：战士、射手、法师、坦克、刺客。
- 三路兵线、防御塔、水晶、AI 敌方英雄。
- 普攻、Q/E/R 技能、技能冷却、升级、金币、装备购买。
- 技能范围预览、技能点、Q/E/R 技能等级和大招等级解锁。
- 小地图、计时器、比分、经验条、圆形技能按钮、战绩面板。
- 粒子、线性光效、伤害飘字、击杀/升级/摧毁横幅。
- 三种模式已有基础差异：标准、训练、快速。

主要不足：

- 英雄技能机制还偏简单，缺少控制、位移限制、护盾持续时间、持续伤害、斩杀等机制。
- 地图只有三路，缺少野区、草丛、河道、中立资源。
- 装备只有 3 类叠加，缺少装备树、被动、推荐购买。
- AI 只有简单追击和攻击，缺少补兵、撤退、守塔、打野、团战判断。
- 战斗 UI 还有细节缺失：锁定目标。
- 没有音效、设置页、结算页、战斗记录。

## 对照拆解

| 模块 | 同类王者 MOBA 常见表现 | 当前游戏 | 需要实现 |
| --- | --- | --- | --- |
| 大厅 | 玩家信息、模式入口、活动/任务、货币、开始对局 | 有大厅和模式卡 | 补玩家头像、货币栏、任务栏、模式说明、返回/设置 |
| 模式 | 匹配、排位、训练、娱乐模式规则不同 | 三种模式只有基础规则差异 | 每个模式独立规则、AI 强度、开局资源、胜利条件 |
| 英雄选择 | 英雄分类、头像网格、技能预览、确认按钮 | 5 英雄卡片 | 分类筛选、锁定确认、技能说明面板、阵容预览 |
| 加载页 | 双方阵容、英雄头像、进度、提示 | 1v1 加载页 | 扩展到 3v3/5v5 表现，显示模式和英雄定位 |
| 地图 | 三路、野区、河道、草丛、中立目标 | 只有三路 | 野怪营地、草丛隐身、河道、主宰/暴君类原创目标 |
| 兵线 | 分路出兵、兵种差异、炮车/超级兵 | 普通小兵 | 近战兵、远程兵、攻城兵、破高地后的强化兵 |
| 防御塔 | 攻击递增、塔下保护、兵线抗塔优先级 | 自动攻击 | 攻击目标优先级、连续攻击加伤、塔范围提示 |
| 水晶 | 基地目标、攻击、防守压力 | 会攻击 | 水晶护盾、濒危特效、胜负结算 |
| 英雄成长 | 等级、技能升级、经济、装备 | 等级提升基础属性和技能伤害 | 技能等级、可加点、装备被动、成长曲线 |
| 装备 | 装备树、推荐装、属性叠加、被动效果 | 3 类装备叠加 | 攻击/法术/防御/移速/打野装，装备合成和被动 |
| 技能 | 指示器、命中反馈、控制效果、范围预览 | Q/E/R 基础技能和特效 | 技能预览圈/扇形/直线，眩晕/减速/护盾/持续伤害 |
| 操作 | 虚拟摇杆、普攻键、技能键、取消施法 | 键鼠控制 + 视觉摇杆 | 锁定目标、自动寻敌、技能方向预览、取消施法 |
| 小地图 | 兵线、英雄、塔、信号 | 基础小地图 | 点击信号、敌人消失、野怪刷新点、塔状态 |
| 战斗提示 | 击杀、连杀、推塔、经济经验反馈 | 横幅和飘字 | 连杀、助攻、终结、推塔播报、金币/经验飘字 |
| AI | 对线、撤退、团战、打野、守塔 | 简单追击 | 状态机 AI：发育、进攻、防守、回城、打野 |
| 音效 | 技能音、击杀音、按钮音、环境音 | 无 | 使用原创/可用音效资源或程序化简单音效 |
| 结算 | 胜负页、战绩、经济、伤害、评分 | 只有胜利弹窗 | 完整结算页、数据统计、重新开始 |

## 分阶段实施计划

### 阶段 1：基础体验补齐

目标：让当前单机 1v1 原型更像一个完整可玩的 MOBA 对局。

任务：

- 增加回城机制：按 `B` 回城，读条期间受伤/移动打断，成功后回到水晶并回血。
- 增加召唤师技能：闪现、治疗、惩击三选二或固定两个。
- 增加技能范围预览：按住/按键时显示直线、圆形、扇形预览。已完成。
- 增加技能升级：英雄升级后获得技能点，Q/E/R 可升级，伤害和冷却变化。已完成。
- 增加战绩面板：按 `Tab` 显示击杀、死亡、金币、等级、装备。已完成。
- 增加结算页：胜利/失败后展示时长、击杀、推塔、金币、等级。

验收标准：

- 一局从大厅到结算完整闭环。
- 玩家能清楚看到技能范围、成长收益、战斗结果。
- README 更新操作说明。

### 阶段 2：地图和兵线丰富

目标：让地图不再只是三条线，加入 MOBA 核心资源争夺。

任务：

- 增加野区区域和野怪营地。
- 增加原创中立 Boss：例如 `远古守卫` 和 `星辉巨像`。
- 增加野怪刷新计时和击杀奖励。
- 增加草丛区域：进入后对远距离敌人隐藏。
- 增加兵种：近战兵、远程兵、攻城兵。
- 摧毁一路高地塔后，该路刷新强化兵。

验收标准：

- 地图上有可争夺资源。
- 打野/推线/拆塔三种目标都能带来收益。
- 小地图能显示野怪和兵线状态。

### 阶段 3：装备系统重做

目标：装备从简单叠加变成有选择、有路线、有被动。

任务：

- 把装备拆到独立 `equipment_data.py`。
- 增加装备分类：攻击、法术、防御、移动、打野。
- 增加装备合成树：小件 -> 大件。
- 增加装备被动：暴击、吸血、护盾、减速、灼烧、破甲。
- 增加推荐装备栏和一键购买。
- 商店 UI 改成多列列表，显示价格、属性、被动。

验收标准：

- 至少 12 件装备。
- 不同英雄有不同推荐出装。
- 装备选择能明显改变打法。

### 阶段 4：英雄机制扩展

目标：让英雄不只是数值不同，而是玩法不同。

任务：

- 增加控制效果系统：眩晕、减速、沉默、击退。
- 增加状态系统：护盾、持续伤害、治疗、免伤、加速。
- 增加 3 个新英雄：
  - 辅助：治疗/护盾/控制。
  - 打野：高机动/惩击收益。
  - 法刺：位移/爆发/刷新机制。
- 给每个英雄增加被动技能。
- 英雄选择页增加职业筛选。

验收标准：

- 至少 8 个英雄。
- 每个英雄有被动 + Q/E/R。
- 至少 4 种状态效果能在实战中看出来。

### 阶段 5：AI 升级

目标：让敌方不再像简单移动靶。

任务：

- AI 改成状态机：
  - 对线
  - 补兵
  - 撤退
  - 守塔
  - 推塔
  - 打野
  - 追击
  - 回城
- AI 会判断血量、塔范围、敌我人数、技能冷却。
- 不同模式使用不同 AI 参数。
- 训练营 AI 明显保守，快速对决 AI 更激进。

验收标准：

- 敌方会残血撤退。
- 敌方会优先守塔或推塔。
- 敌方会使用技能连招。

### 阶段 6：表现和音效

目标：把视觉反馈和操作反馈做完整。

任务：

- 增加原创按钮音、技能音、击杀音。
- 增加屏幕震动效果：大招、推塔、水晶爆炸。
- 增加技能命中特效分层：起手、飞行、命中、消散。
- 增加塔攻击警告线。
- 增加水晶濒危特效。
- 增加经济、经验、冷却完成提示。

验收标准：

- 每个技能有明确起手、飞行、命中反馈。
- 大招、推塔、击杀有明显区别。
- 玩家不看日志也能理解发生了什么。

### 阶段 7：代码结构继续拆分

目标：避免 `main.py` 再次膨胀。

任务：

- `game_data.py` 保留纯数据和基础实体。
- 新增 `systems/combat.py`：伤害、状态、击杀、经验。
- 新增 `systems/ai.py`：AI 状态机。
- 新增 `systems/render.py`：绘制函数。
- 新增 `systems/effects.py`：粒子、光线、飘字、横幅。
- 新增 `screens/`：语言页、大厅页、英雄选择页、加载页、结算页。

验收标准：

- `main.py` 控制在 300 行以内。
- 每个系统可以单独改动。
- 新增英雄只需要改数据和少量技能逻辑。

## 推荐优先级

1. 阶段 1：回城、召唤师技能、技能范围预览、结算页。
2. 阶段 2：野区、野怪、草丛、兵种。
3. 阶段 3：装备系统重做。
4. 阶段 4：英雄机制扩展到 8 个以上。
5. 阶段 5：AI 状态机。
6. 阶段 6：音效和高级表现。
7. 阶段 7：代码结构继续拆分并准备迁移到 `pygame`。

## 需要确认的问题

1. 目标优先做成单机 1v1，还是扩展成 3v3/5v5 的假队友 AI？
2. 继续坚持 Python 标准库 `tkinter`，还是允许切到 `pygame` 以便更好做动画、音效和输入？
3. 英雄数量第一目标是 8 个、10 个，还是更多？
4. 是否需要加入鼠标拖拽式技能瞄准，还是保持键盘按键立即释放？
5. 音效是否允许使用可商用免费素材，还是只做程序化简单音效？
6. 是否要保留中英文双语，还是后续主要维护中文？
